# SECURITY.md

**Secure Medical Data Gateway (SMDG)** — Политика и процедуры безопасности

**Версия:** 1.1  
**Дата:** 18 апреля 2026  
**Классификация:** Конфиденциально (медицинские данные)

---

## 1. Обзор

SMDG — это критически важная система обработки медицинских данных.  
Все механизмы безопасности являются **обязательными** и должны выполняться в соответствии с настоящим документом.

**Цели безопасности:**
- Обеспечение конфиденциальности, целостности и доступности медицинских данных
- Соответствие требованиям ФЗ-152, HIPAA-подобным стандартам и принципам Zero Trust
- Полный аудит всех действий с данными

Подробное описание соответствия регуляторным требованиям (оператор ПДн, сроки хранения, право на забвение, журнал передач) см. в **[COMPLIANCE_TEMPLATE.md](COMPLIANCE_TEMPLATE.md)**.

## 2. Модель угроз (Threat Model)

Основные угрозы, от которых защищён SMDG:
- Несанкционированный доступ к зашифрованным файлам
- Перехват данных в транзите
- Атаки на аутентификацию (brute-force, credential stuffing)
- Загрузка вредоносных файлов
- Компрометация ключей шифрования
- Утечка через временные файлы или логи
- Внутренние угрозы (инсайдеры)

---

## 3. Аутентификация и Авторизация

### 3.1. Аутентификация
- JWT в **HttpOnly + Secure + SameSite=Lax** cookies (`access_token`)
- Срок жизни токена — 60 минут
- 2FA (TOTP) является обязательной рекомендацией для всех пользователей системы. После первой успешной авторизации         пользователю предлагается настроить двухфакторную аутентификацию.
- Для пользователей с ролью admin использование 2FA обязательно.

### 3.2. Авторизация
- Роли: `admin`, `doctor`, `user`
- Защита через FastAPI Depends: `get_current_admin()`, `get_current_doctor()`, `get_current_user()`

---

## 4. Защита данных

### 4.1. Шифрование данных в покое
- Алгоритм: **age** (asymmetric encryption)
- Ключи хранятся в `/app/keys/` через Docker Secrets
- **Обязательная автоматическая ротация ключей** с перешифровкой всех файлов

### 4.2. Шифрование в транзите
- TLS 1.3 через Nginx
- Обязательный редирект HTTP → HTTPS
- HSTS (в продакшене)

### 4.3. Хранение паролей
- Алгоритм: **Argon2** (рекомендованные параметры: time_cost=2, memory_cost=102400, parallelism=8)

---

## 5. Безопасность загрузки файлов

- Белый список расширений и MIME-типов
- Запрет опасных расширений
- Двойная проверка MIME (libmagic + заголовки)
- **Обязательное сканирование ClamAV** перед шифрованием
- Ограничение размера файла (`MAX_UPLOAD_SIZE_MB`)

---

## 6. Rate Limiting

- Используется **slowapi + Redis**
- Детализированные лимиты по типам эндпоинтов — см. **[API.md §5](API.md#5-rate-limiting)**
- При превышении — статус 429

## 7. Аудит и Логирование

- Все операции логируются через `AuditLogger`
- Два формата: JSON (по дням) + CSV (с ротацией 10 МБ)
- Логи хранятся в `./audit_logs/`

## 9. Обязательные процедуры

### 9.1. Обновление зависимостей
- Выполняется **еженедельно** командой DevOps
- Проверка через `poetry update` + `bandit`
- Все обновления тестируются в staging-окружении

### 9.2. Периодические аудиты безопасности
- Полный аудит кода и инфраструктуры — **раз в 3 месяца**
- Проверка ключей и ротация — **раз в месяц**
- Сканирование образов Docker — **при каждом деплое**

### 9.3. Процедура реагирования на инциденты (Incident Response)

1. **Обнаружение** — в течение 15 минут
2. **Классификация** — в течение 30 минут
3. **Содержание** — изоляция скомпрометированных систем
4. **Уведомление** — ответственные лица + руководство в течение 1 часа
5. **Ликвидация** — в течение 4 часов
6. **Пост-анализ** — в течение 48 часов с составлением отчёта

---

## 10. Политика раскрытия уязвимостей (Responsible Disclosure)

- Все найденные уязвимости должны сообщаться **только** владельцу системы
- Срок ответа на отчёт — **48 часов**
- Публичное раскрытие возможно только после исправления и уведомления

## 11.5 Безопасность DICOM Viewer

DICOM Viewer обрабатывает медицинские изображения и требует дополнительных мер защиты:

### 11.5.1 Защита расшифрованных данных

- **Расшифровка ТОЛЬКО в память** — временные файлы создаются в `/decrypted/` и немедленно удаляются в `finally` блоке
- **Никаких расшифрованных файлов на диске** после завершения запроса
- View-токен имеет **ограниченный TTL** (по умолчанию 15 минут)

### 11.5.2 Контроль доступа

- Просмотр DICOM требует **авторизации через JWT** для генерации view-токена
- Все запросы к DICOM API авторизуются через **view_token** с проверкой TTL
- **Feature Flag** `DICOM_VIEWER_ENABLED` позволяет полностью отключить подсистему

### 11.5.3 Аудит

Все действия DICOM Viewer логируются:
- `dicom.view_initiated` — кто открыл viewer
- `dicom.metadata_accessed` — кто запросил метаданные
- `dicom.streamed` — успешная передача данных
- `dicom.stream_failed` — ошибка при обработке

### 11.5.4 Зависимости

| Библиотека | Назначение | Риск |
|---|---|---|
| pydicom | Парсинг DICOM | Средний (обработка ненадёжных файлов) |
| numpy | Обработка пикселей | Низкий |
| pillow | Конвертация в PNG | Низкий |

### 11.5.5 Ограничения

- **Сжатые DICOM** (JPEG2000, JPEG-LS) могут не поддерживаться без дополнительных кодеков (GDCM)
- **Multi-frame** файлы обрабатываются как single-frame (берётся первый кадр)
- Максимальный размер файла: `DICOM_MAX_STREAM_SIZE_MB` (по умолчанию 500 МБ)

## 11.6 Audit Export Security

Экспорт журнала аудита (**GET /api/admin/audit/export**) возвращает агрегированные записи операций за период и может включать имена пользователей, действия (`action`), IP-адреса и метаданные из поля **`metadata`** в JSON-журнале.

### 11.6.1 Контроль доступа

- Эндпоинт доступен **только** после успешной аутентификации и при роли **`admin`** или **`super_admin`** (`get_current_admin`).
- Пользователи с ролями **`doctor`** и **`user`** получают **403 Forbidden** независимо от параметров запроса.
- Рекомендуется активировать **2FA** для всех учётных записей администраторов и ограничить число администраторов до минимально необходимого.

### 11.6.2 Защита от утечек данных

- Отчёты передаются по HTTPS (TLS); в production не используйте plain HTTP для административных операций.
- Имена скачиваемых файлов задаются через префикс **`AUDIT_EXPORT_DOWNLOAD_PREFIX`**; не включайте в них персональные данные пациентов из метаданных без необходимости.
- CSV и Excel может открыть Excel/LibreOffice локально у администратора — распространение файлов экспорта должно регламентироваться политикой ИБ так же, как доступ к первичному журналу аудита (`audit_logs`).
- При экспорте в **PDF** используйте **`AUDIT_EXPORT_PDF_FONT_PATH`** только к доверенному файлу шрифта (минимизация поверхности атаки в образах с кастомными путями).

### 11.6.3 Журналирование и мониторинг

- Ошибки чтения логов и ошибки генерации отчёта записываются на сервере (**500** клиенту); мониторинг логов приложения позволяет выявить аномальное число запросов экспорта.
